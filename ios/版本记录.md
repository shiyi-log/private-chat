# 版本记录

本文档记录 iOS 客户端仓库的重要版本变更。

## v0.4.9-private-default-english-runtime-cleanup

- 修复 iOS 默认英文第一批普通运行入口中的上游品牌漏项，覆盖联系人加入通知、手机号错误/封禁邮件模板、频道/群公开链接、缓存计算、后台定位权限、清空聊天云端提示、网站登录、Secret Chat 链接预览、联系人重置、Passport 主入口、分享登录、语言包、登录验证码、Passcode 锁定、联系人/蜂窝数据/通知权限和壁纸权限。
- 将 iOS 默认英文 Passport FAQ 链接从 `telegram.org` 改为 `privatechat.local` 私有占位地址，并将公开链接示例从 `t.me` 改为 `privatechat.local`。
- 扩展 `scripts/verify_private_chat_ios_config.py`，新增第一批普通运行入口门禁，当前 iOS 私有化静态验证为 `456/456` 项通过。
- 当前仍未处理 Live Stream、内置浏览器、WebApp、冻结账号、年龄验证、Profile Level、部分媒体权限和深层商业/策略功能中的剩余文案；后续继续分批清理或按私有产品策略隐藏、重做、替换。

- `scripts/verify_private_chat_ios_config.py` 已扩展到旧发布校验脚本、扩展构建 plist、上游 merchant / Bundle ID 门禁，当前验证结果为 `353/353` 项通过。

## v0.4.5-simulator-build-and-private-display-name

- 新增模拟器专用无签名 Xcode 工程生成入口：`//Telegram:Telegram_simulator_xcodeproj`，仅包含 iOS Simulator Debug 目标，避免本地模拟器构建被真机 provisioning profile 阻断。
- 修复 `generateProject --disableProvisioningProfiles` 未完整传递到 Bazel 项目生成参数的问题；禁用 provisioning profile 时允许缺少 `aps-environment`，用于本地模拟器构建。
- 将本地最小开发配置中的 `api_id`、`api_hash`、`team_id` 从占位符改为合法开发格式值，用于生成工程和本地模拟器构建；这些值不是生产发布凭据，正式发布前必须替换为私有正式配置。
- 修复 Xcode 26.5 + rules_xcodeproj 下 framework bundle 复制后的权限和 Swift module 目录问题，避免 `Info.plist` 写入失败以及 `.swiftmodule/.swiftdoc/.swiftsourceinfo` 复制失败。
- 修复实际构建产物 `TelegramInfoPlist` 中的主 App 显示名、Bundle Name、权限说明和主题 UTI，最终 `.app` 对外显示为 `Private Chat`，Bundle ID 为 `com.privatechat.ios`。
- `scripts/verify_private_chat_ios_config.py` 已扩展到实际构建用 `Telegram/BUILD` 的主 App plist 片段，当前验证结果为 `290/290` 项通过。
- 已使用 Xcode 26.5 / iOS 26.5 Simulator 完成工程生成、Debug 构建、安装和启动冒烟验证；`xcrun simctl launch` 已返回 `com.privatechat.ios` 进程号。
- 仍未完成 iOS 登录和消息互通测试：模拟器当前连本机 `127.0.0.1:10443`，真机和多端互通仍需要固定局域网 IP 或公网域名；真机/发布包仍需要真实 Apple 签名证书和 provisioning profile。
